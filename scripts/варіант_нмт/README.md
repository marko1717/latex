# Генератор тренувальних варіантів НМТ з математики

Складає варіант за структурою НМТ 2023–2026: **15 тестових** завдань (1 бал),
**3 на відповідність** (до 3 балів) і **4 з короткою відповіддю** (по 2 бали) —
разом 32 бали. Кожне завдання — або справжнє завдання НМТ 2023–2026 із бази,
або **аналог**: нове завдання, зроблене за зразком справжнього, з тими самими
«пастками» в дистракторах і перевірене двома незалежними розв'язувачами та рецензентом.

```bash
python3 scripts/варіант_нмт/варіант.py                      # один варіант, лише оригінали
python3 scripts/варіант_нмт/варіант.py --нових 6            # 6 місць із 22 -- аналоги
python3 scripts/варіант_нмт/варіант.py --кількість 4        # 4 варіанти без спільних завдань (для класу)
python3 scripts/варіант_нмт/варіант.py --роки 2025-2026 --складність складний --seed 7
```

Результат — `варіанти/Варіант_N.tex` (і `Варіант_N_без_водяного_знака.tex` для вчителів);
на останній сторінці — ключ і джерело кожного завдання (рік, сесія, номер або «аналог»).
Використані завдання записуються у `варіанти/журнал.json`, і наступні варіанти їх не
повторюють (`--дозволити-повтори` вимикає це, `--без-журналу` — пробний запуск). `--номер N`
для вже наявного номера перескладає цей варіант: його старий запис у журналі замінюється.
`--перезібрати 1 3` лише перезаписує `.tex` цих варіантів з тими самими завданнями, що в журналі
(після виправлень умов чи рисунків у базі); склад не змінюється.

## Алгоритм

1. **Слоти.** Варіант — це 22 слоти, у кожного своя категорія (`спільне.КАТЕГОРІЇ`):

   | № | тестові (1–15) | № | відповідність і коротка відповідь |
   |---|---|---|---|
   | 1 | арифметика: проста чи практична задача, дроби, відсотки | 16 | вирази: значення, проміжок, спрощення |
   | 2 | статистика | 17 | функції: графіки, властивості, екстремуми |
   | 3 | планіметрія: просте (кут, довжина відрізка, практичне) | 18 | планіметрія: елементи, площі, кути, радіуси |
   | 4 | нерівність або система нерівностей | 19 | функціональне: похідна, первісна, прогресія |
   | 5 | стереометрія (прямі й площини, многогранники) | 20 | статистика, ймовірність, комбінаторика, відсотки |
   | 6 | вирази: степені, корені, ФСМ, спрощення | 21 | стереометрія: перерізи, координати, комбінації тіл |
   | 7 | показникове, логарифмічне чи тригонометричне рівняння | 22 | рівняння з параметром |
   | 8 | графік чи властивість функції | | |
   | 9 | твердження планіметрії | | |
   | 10 | похідна, первісна чи прогресія | | |
   | 11 | комбінаторика або ймовірність | | |
   | 12 | координати в просторі, вектори | | |
   | 13 | тригонометричний вираз | | |
   | 14 | планіметрія: площа, периметр чи елемент за рисунком | | |
   | 15 | рівняння (лінійне, квадратне, модульне, ірраціональне) чи система | | |

   Порядок узято з сесій НМТ-2026: `структура.py` рахує, яка категорія на якій позиції
   трапляється найчастіше, і розставляє 15 тестових категорій по позиціях задачею про
   призначення (див. таблицю частот у виводі скрипта).

2. **Каталог** (`scripts/data/варіант_каталог.json`, будує `каталог.py`) — усі 1597
   унікальних завдань бази з метаданими: теми, тип, рік, сесія й номер (для 2026 — з бази,
   для 2023–2025 — зіставленням із PDF-посібником «НМТ 2023–2025»), категорія слота,
   складність 1–3, дефекти і **перевірена відповідь**. Відповіді отримано так:
   - розв'язувач A розв'язує кожне завдання наосліп (без ключів);
   - якщо відповідь A збігається з надійним ключем (офіційний ключ 2026, таблиця
     «Правильні відповіді» посібника 2024–2025, ключі тематичних збірників) — прийнято;
   - інакше незалежний розв'язувач B; збіг A і B без суперечності з ключем — прийнято;
   - будь-яка розбіжність чи позначений дефект — арбітр (бачить обидва розв'язки, ключі й
     текст оригіналу, може відкрити сторінку PDF). Завдання з дефектом у варіант не беруться.

3. **Аналоги** (`scripts/data/варіант_згенеровані.json`) — для кожної категорії генератор
   бере справжні завдання-зразки, розбирає, яку помилку моделює кожен дистрактор, і складає
   нове завдання з тією самою суттю й складністю. Кожен аналог перевіряють два розв'язувачі
   наосліп і рецензент (формат НМТ, одна правильна відповідь, якість дистракторів, рисунок
   відповідає умові); відхилені — ремонтуються й перевіряються знову, неремонтовні відкидаються.
   Нові аналоги генерує Claude (воркфлоу), скрипт лише бере їх із бібліотеки.

3а. **Рисунки.** Кожне завдання з рисунком (бази й аналогів) рендериться окремою картинкою, і
   рецензенти перевіряють, чи рисунок відповідає умові й відповіді та чи його можна прочитати
   (поле `рисунок_огляд`: ok / дрібниця / вада). Завдання з вадою рисунка у варіант не беруться.

3б. **Типи не повторюються.** Кожне завдання має тип за темою бази (прогресія, тригонометрія,
   логарифми, показникові, похідна, первісна, статистика, ймовірність, кожна фігура й кожне тіло ...,
   `спільне.РОДИНИ`). У варіанті кожен тип трапляється щонайбільше раз, окрім функцій. Слоти з
   найвужчим вибором типів заповнюються першими; якщо розкласти не вдалося -- варіант складається наново.
   Ключі трьох завдань на відповідність (16--18) різні: однакові поспіль виглядали б як підказка.

4. **Вибір.** Для кожного слота береться випадкове (за `--seed`) придатне завдання його
   категорії: спершу рік (2026 : 2025 : 2024 : 2023 = 3 : 2,5 : 2 : 1,5, незалежно від того,
   скільки завдань має рік), потім завдання цього року; теми в одному варіанті намагаються не
   повторюватися, `--складність` зсуває ймовірності до легших чи складніших завдань.
   `--нових K` — K випадкових слотів заповнюються аналогами.
   `--нових 22` — повністю авторський варіант (лише аналоги).
   №14 (обчислювальна планіметрія) — одне з найважчих тестових завдань: туди беруться лише
   завдання, які два незалежні рецензенти оцінили в 4+ кроки міркування (поле `кроки` каталогу й
   аналогів, `варіант.МІН_КРОКИ`). Нові кандидати в цей слот треба так само оцінити, інакше вони
   у №14 не потраплять.

5. **LaTeX.** Кожне завдання вставляється зі «своїми» макросами теми, без позначок року
   (`--показати-роки` лишає їх), з інструкціями перед 1, 16 і 19 як на НМТ.

## Файли

* `спільне.py` — категорії, структура, читання бази, нормалізація відповідей.
* `каталог.py` — побудова й оновлення каталогу (зберігає відповіді при повторному запуску;
  якщо завдання в базі змінилося, шукає його за схожістю).
* `структура.py` — частоти категорій за позиціями в сесіях 2024–2026.
* `варіант.py` — складання варіантів.
* `аналоги.py` — приймання згенерованих аналогів (кожен компілюється окремо) і `перегляд` —
  PDF з усіма аналогами бібліотеки по категоріях.

## Як додати нові аналоги

Попросіть Claude «згенеруй ще аналогів для категорії …»: воркфлоу бере справжні зразки категорії
з каталогу, генерує, перевіряє двома розв'язувачами й рецензентом, ремонтує відхилені; прийняті
додаються командою `аналоги.py додати РЕЗУЛЬТАТ.json ТЕКА_ЗРАЗКІВ` і проходять огляд рисунків.

## База зразків (для подальшого використання)

`python3 scripts/варіант_нмт/зразки.py` зводить усі джерела в `локальне/зразки.json` (поза git):
база НМТ (перевірені відповіді й категорії), перенабрані офіційні ЗНО, zno.osvita.ua (текст з формулами;
лише зразки, не для поширення) і картинки ClassTime (картинка + розпізнаний текст + відповідь).
Дублікати між джерелами зведено в один запис; у кожного запису є джерело, умова, відповідь, тип,
орієнтовний слот і позначка «поширення». Звідси генератор бере зразки для авторських аналогів.
Як оновлювати джерела -- `scripts/зно_osvita/`, `scripts/classtime/`, `scripts/зно_офіційні/`.
